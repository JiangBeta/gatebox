# ADR-041：架构 V4（以统一框架为组织原则的总纲升级）

- 状态：已接受
- 日期：2026-09-17
- 前置：ADR-027（生命周期边界）、ADR-028（组件运行时接口）、ADR-031/032（分层）、ADR-036（扩展平台）、ADR-037 ~ ADR-039（插件拔插化）、ADR-040（应用网关统一框架）
- 取代：`docs/architecture.md`（v3 总纲）升级为 v4；v3 内容被吸收，原文由 git 历史保留

## 背景

ADR-040 已定义「统一描述 / 可观测 / 声明式调和」框架，但 v3 总纲仍以「组件运行时 + 扩展平台」为主叙事，导致同一件事存在多套描述：

- `component.Descriptor`（生命周期元数据，architecture.md v3 §3.1）
- `component` 可选接口（Runnable/Health/Configurable/…，v3 §3.2）
- `extension.Provider` / `Capability`（能力注册表，v3 §4）
- ADR-040 的「身份 + 功能 + 四契约」

此外，v3 的自动化联动是**隐式**的（docker label → 派生 Service → Caddyfile → `/load`，写在 `reloadCaddy` 与 20+ handler 里），没有显式依赖图、失效追踪与调和，已知缺陷（改 Domain/Credential 不触发重载、Port 需手动重启、改 Variable 不回填 compose）。

因此需要一次总纲级的收敛：把 ADR-040 从「框架定义」提升为「系统组织原则」，据此重排 v3 的本体、分层、API、持久化、前端与分期。

## 决策

### 1. V4 与 V3 的关系：演化替代

V4 取代 V3 成为**唯一现任总纲**（`docs/architecture.md` 就地升级）。V3 的成熟决定（组件生命周期六层、制品源三通道、插件分发、分层门禁、设计 token、运行时目录）作为 V4 的**承载**保留；V3 原文由 git 历史承载（文档不另存双档）。

### 2. 主叙事：统一描述 / 可观测 / 声明式调和

系统本体 = **描述符 + 功能地图 + 观测 + 调和器**；v3 的「组件运行时 / 扩展平台 / 插件引擎」降为**承载与实现细节**。

### 3. 描述符收敛为唯一 `Descriptor`

扩展 v3 的 `component.Descriptor` 为「身份 + 功能清单 + 四契约（配置 / 信息 / 观测 / 生效）」；`extension.Provider` 的能力声明并入「功能」部分；`component` 的可选接口作为四契约的运行时实现面。**插件 manifest 编译为同一 `Descriptor`**，核心与插件同构（ADR-036 I1）。

### 4. 依赖图：类型端口 + 实例绑定

- 信息契约 = 组件声明 `consumes` / `produces` 的**信息类型端口**（`service` / `domain` / `cert` / `port` / `variable` / `label` / `ip`…）。
- 事实间**引用**（`Domain.credentialID`、`Service.fragmentIDs`、`ProxyDomain.rootDomain`…）给出**具体实例**的边。
- 依赖图 = **类型骨架 + 实例绑定**；事实集由**中央事实注册表**声明（事实属于系统，不属于组件）。

### 5. 新增包与依赖方向

新增职责单一的包：

| 包 | 职责 |
|---|---|
| `internal/graph` | 事实注册表 + 引用解析 + 依赖图推导 |
| `internal/reconcile` | 意图 + 调和器 + Run/Step 记录 |
| `internal/observe` | 观测聚合（state/activity/logs/metrics）+ 事件总线 |

依赖方向（`depguard` 强制）：

```
handler → service → {reconcile, repository}
reconcile → {graph, component, observe, repository}
graph → {model, component}
observe → {component, model}
plugin → {component, extension}
component → {model, source}
extension → model
model → （零依赖）
```

`service` 收缩为「**校验 + 落库 + 提交意图 + 同步返回 runId**」，不再直接调用 `adapter/gateway`（那类逻辑移入组件的调和函数）。

### 6. 触发与执行

- **触发**：level-triggered。写操作 = 落库事实 + `reconciler.Trigger(意图)`（去抖合并）+ 周期兜底；HTTP 写接口**同步返回「已受理 + runId」**，进度经事件流推送。
- **执行**：按依赖图**拓扑序**执行，无依赖边可**同层并行**；失败**不全局回滚**，标记 `degraded/error` 并在下轮收敛重试（ADR-040 §3.4）。
- **收敛**：幂等重放 + 失败重试 + 漂移检测。

### 7. 观测

- 契约：新增 **`Activity`** 可选接口（不合并为万能大接口）；`state` 沿用 `Health.Status`，`logs` 沿用 `Loggable`，`metrics` 留 `Status.Metrics`。
- 存储：Run/Step **内存环形 + BoltDB 落盘**（条数 + 天数双限）；Event **仅内存**；Logs **不落库**，仅做关联。
- 推送：观测事件（Run/Step 推进、state/activity 变化）走 **SSE**；WebSocket 保留给需要双向的交互（容器 exec/终端/部署进度）。

### 8. API 契约新增

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/v1/descriptors` | 全部组件描述符（前端派生引擎数据源） |
| GET | `/api/v1/graph?view=component\|function&root=<tag>` | 功能地图 / 依赖图 |
| GET | `/api/v1/runs` · `/api/v1/runs/{id}` | 运行记录列表 / 详情 |
| GET | `/api/v1/components/{id}/status\|activity\|logs` | 局部观测 |
| GET | `/api/v1/events` | SSE：Run/Step 推进与状态变化 |
| GET | `/api/v1/schema/{factKind}` | 配置契约（驱动 Form/YAML） |

遵循 v3 §10 API 标准，由后端产出 OpenAPI → 前端生成 TS 类型。投影 `/api/v1/extensions/me/projection/*` 不变。

### 9. 插件 manifest：additive 扩展

保持 `apiVersion: gatebox/v2`，**新增可选字段**：`provides`（功能）、`consumes` / `produces`（信息契约）、`observability`（观测契约）、`effect`（生效契约）。属**新增可选字段 = minor**（ADR-037 §5），不升 major；缺失字段的旧插件编译为「最小描述符（仅功能，无信息/观测/生效契约）」，保证向后兼容。GateBoxStore 的 `schema/` 与文档同步（先主仓库后 Store）。

### 10. 前端派生引擎

- 位置：`lib/schema/`（业务无关的 schema → 渲染引擎）+ `app/components/`（通用 Form/YAML/卡片渲染）+ `modules/*`（域定制）。
- 字段类型（精简起步）：`text / number / select / switch / textarea / array / object / reference`，属性含 `advanced` / `summaryFields`；`duration / json / record / timeRange / arrayPresentation` 等按需后置。
- 双模：**只对有文本源的对象**（compose 已有、Fragment、后续 gatebox.conf）做 Form ↔ YAML；无文本源者 = Form + 只读预览（如 Caddyfile 预览）。
- 功能地图：`@vue-flow/core` + **双层投影**（组件视角 / 功能视角）+ **手写分层布局**（BFS 深度分列 + 父中心对齐 + 冲突下推）；节点位置按内容指纹存 localStorage；点击打开详情/编辑抽屉，图上不直接编辑。

### 11. 分期

纵轴 = **L1 静态自描述 → L2 运行态观测 → L3 执行可追踪**；横轴顺序 = 先内建组件（caddy/acme/docker/ddns），后插件。**首个闭环 = 网关域**（Service/Domain/Credential/Port/Variable）：L1 描述符 + 功能地图；L2 状态/活动；L3 用 `reconcile` 替换 `reloadCaddy` 并修掉已知触发缺口。v3 的 P0–P5 作为「已完成的承载建设」并入，不再并列。

### 12. 文档形态

就地升级 `docs/architecture.md` 为 v4；新增本 ADR；更新 `glossary.md`、`PRD.md` 与 ADR 索引；V4 设计同步发布一份到 `JiangBeta/GateBoxStore` 的 `docs/`（供插件作者对齐四契约）。

## 后果

- **优点**：消除多套描述（唯一 Descriptor）；把隐式流转显式化为依赖图；顺带修掉已知触发缺口；异种组件与插件统一纳入；为可观测与自动化提供同一底座；分层仅新增职责单一的包，零回归风险可控。
- **代价**：`service` 职责收缩需迁移既有 handler→adapter 调用；新增 `graph/reconcile/observe` 三个包与对应 API/持久化；v2 manifest 的 additive 字段需 GateBoxStore 与 schema 同步；插件若要用信息/观测/生效契约需声明新字段（可选，不阻塞旧插件）。
- **范围**：本 ADR 只定 V4 结构与分期；各包的详细设计、依赖图推导算法、调和器实现、前端派生引擎细节，另立单位级设计文档。
