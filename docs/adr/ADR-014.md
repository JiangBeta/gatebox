# ADR-014：Docker 客户端——自研轻量 HTTP 封装（取代 moby SDK）

- 状态：已接受（取代 PRD 原「moby SDK」选型）
- 日期：2026-08-25

## 背景

PRD 原定 Docker 交互走 moby SDK（`github.com/docker/docker/client`）。落地前实测发现两个问题：

1. **该 import 路径已不可用**。moby 已将 client/api 拆分为独立模块 `github.com/moby/moby/client`，当前版本 **v0.5.1**（0.x，无稳定性承诺），且方法签名整体变更：`ContainerList` 返回值改为 `ContainerListResult{Items}`、`ContainerStats` 参数改为 options 结构、`ContainerExecAttach` 改名为 `ExecAttach`。**PRD 里写的选型指向的包已经不存在。**
2. **体积并非主要矛盾**。实测（`CGO_ENABLED=0` + `-s -w`）：纯标准库 5.95 MB，引入 SDK 后 7.31 MB，**增量仅 1.36 MB**。但 SDK 拖入 **20 个第三方模块，其中 8 个是 OpenTelemetry 依赖链**，而 GateBox 不做分布式追踪。

## 决策

**自研轻量 HTTP 封装**：标准库 `net/http` + unix socket 直连 Docker Engine API，请求路径锁定 API 版本号（`/v1.44/...`；本机 server 为 API 1.55，向后兼容至 1.40）。

- 需自行实现约 **25~30 个端点**，其中 4 个流式：logs / stats / pull / exec。
- 需自行处理 **stdcopy 的 8 字节帧头解析**与 **exec 的连接 hijack**（标准库 `http.Hijacker` 原生支持）。
- 封装为 `DockerClient` 接口，按 `hostID` 解析传输层（本地 unix socket / 未来 tcp+TLS / ssh）。
- **compose 仍走 CLI**——它没有 Engine API 等价物。

## 后果

- 优点：**Engine API 的 HTTP 契约远比 moby 的 Go SDK 稳定**——路径带版本号、有明确向后兼容承诺、十年未断；而 Go SDK 半年内 import 路径与方法签名全变了一轮。零第三方依赖，多主机时 transport 层完全自主。
- 代价：约 25~30 个端点的机械实现量；stdcopy 帧解析与 hijack 必须写对（需单测覆盖跨帧边界）。
- 约束：交付编译使用 `CGO_ENABLED=0`（项目无 cgo 依赖）。
