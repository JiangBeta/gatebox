# ADR-011：运行时目录与工具安装归属

- 状态：已接受
- 日期：2026-08-20

## 背景

控制面生成/管理的文件（BoltDB、Caddyfile、ddnsgo 配置、compose 文件）需要统一落点；外部工具二进制的安装位置需明确。

## 决策

- 统一运行时数据根目录 **`$DATA_DIR`**：位置由用户指定，安装脚本创建并**写入 DB 供全局调用**。
- 布局：`gatebox`（本体二进制）、`db/gatebox.db`、`tools/`（caddy/ddnsgo/docker-compose）、`appData/<projectName>/`（compose + `www/` + `conf/`）。**无全局 `www/`**（file_server 站点文件归各 App 的 `www/`）。
- 工具安装归属：**docker 走系统包管理器**（daemon 是系统服务）；**docker-compose / caddy / ddnsgo 装入 `$DATA_DIR/tools/`** 统一管理，升级各自独立。
- 生成的 Caddyfile 预留 `import` 扩展点（`tools/caddy/user/`），本工具只改写自己生成段，用户手改不被覆盖。

## 后果

- 优点：备份/迁移/排查只需一个目录；扩展点保留用户手改空间。
- 约束：安装脚本需负责目录创建、DB 写入、工具二进制放置。

> **2026-08-25 命名统一**：DB 文件由 `appgateway.db` 改为 `gatebox.db`；应用目录由 `appData/<appName>/` 改为 `appData/<projectName>/`——目录单位是 **compose 项目**而非 App（一个 compose 可含多个容器、产生多个 App），见 ADR-015。

> **2026-09-07 修订（二进制存档入库）**：仓库根 `tools/` 由「不入库（安装脚本放置）」改为**整体入库**——作为外部组件二进制的存档/分发点（caddy / ddns-go / docker-compose / flare 等，linux-amd64/arm64）。安装脚本（单位⑦）仍负责把 `tools/*` 铺到 `$DATA_DIR/tools/*` 运行时布局（注意仓库 `tools/caddy` 是二进制文件，运行时 `$DATA_DIR/tools/caddy/` 是目录：日志 + user 扩展，二进制落 `$DATA_DIR/tools/caddy/caddy`，与 `GATEBOX_CADDY_BIN` 默认路径一致）。
