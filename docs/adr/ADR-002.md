# ADR-002：Caddy 配置生效方式

- 状态：已接受
- 日期：2026-08-20

## 背景

控制面要「改写 Caddy 配置」并让其生效，需保证配置变更不中断业务。

## 决策

**内存生成 Caddyfile → Admin API `/load` 原子加载**，定稿语义：**「先校验、失败回退、成功写入 Caddyfile、零中断」**。

1. 控制面根据 BoltDB 状态在内存中生成完整 Caddyfile；
2. `POST /load`（不先落盘）→ Caddy 先 adapt + 校验，通过才原子替换运行时配置；
3. 成功后把该 Caddyfile 落盘为「配置源备份」，保证磁盘与运行时一致；
4. 校验失败则返回错误、保留旧文件、旧配置继续服务。

## 后果

- 优点：配置错误自动回退、业务零中断、热加载快（不重启进程）。
- 约束：每次 `/load` 是整体加载，控制面需维护「完整 Caddyfile 生成器」。
