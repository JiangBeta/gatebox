# ADR-029：插件模型与分发

- 状态：已接受
- 日期：2026-09-14
- 前置：ADR-027（生命周期边界）、ADR-028（组件运行时接口）
- 参考：Traefik Plugin Catalog（Yaegi/WASM）、Terraform Registry Protocol、Caddy/xcaddy（编译期模块）

## 背景

系统需要「插件」以扩展功能（Coraza 扩展 WAF、Tailscale 扩展 VPN…），并支持通过界面添加/删除。技术现实：Caddy 模块必须编译期注入；独立进程类插件只需下载二进制；系统需要决定是否自建「在线插件服务端」。

## 决策

### 1. v1 数据驱动，不引入解释器/子进程协议

插件 = **manifest 数据** + 通用引擎。三种形态：

| kind | 引擎行为 | 例子 |
|---|---|---|
| `caddy-module` | 替换 active caddy 制品（校验失败回退）+ 注入片段 | Coraza |
| `process` | 下载二进制 → `$DATA_DIR/tools/<id>/` → 启停+健康+声明式操作 | Tailscale / MosDNS / flame |
| `config-only` | 注册 manifest + 写配置 | 轻量指令扩展 |

`kind` 预留扩展位：未来可加 Traefik 式 Yaegi/WASM 或 Terraform 式子进程 gRPC 协议，不破坏 manifest 兼容。

### 2. manifest schema（v1）

字段：`apiVersion / kind / id / name / version / summary / requires / source / artifact / runtime / config / operations / contributions`。详见 `docs/architecture.md` §4.2。

### 3. 页面贡献范围（v1）

仅支持：**导航入口 + iframe 内嵌 + 声明式设置表单（schema）**。任意自定义页面属于未来「代码插件」，不在 v1。

### 4. 状态机与持久化

```
available ──install──▶ installed ──enable──▶ enabled
    ▲                      │                    │
    └─────────remove───────┴──────disable───────┘
                         失败 ──▶ error
```

- BoltDB bucket：`plugins`（状态 + 用户配置）、`component_state`（版本/来源缓存）。
- disable = 保留制品、停用效果；remove = 删制品 + 移除注入配置。

### 5. 分发：静态索引 + 多源 + 签名，无常驻服务端

- 索引 `index.json`（含 `artifact.url / sha256 / manifest`）可静态托管（GitHub Pages / 对象存储 / CDN），签名（minisign/cosign）。
- 制品放 GitHub Releases（含用户自编译的 coraza-caddy）。
- 客户端：拉索引 → 按 `channel` 比较版本 → 校验签名+sha256 → 安装/替换/回滚。
- 索引协议抽象为接口；未来若需动态注册表，客户端无感。

### 6. 安全

安装第三方制品 = 执行代码，风险与 `docker.sock` 同级。必须签名校验 + 显式用户确认。

## 后果

- 优点：无需常驻服务端即可在线安装/升级；插件开发只需写 manifest + 发布制品，门槛低；与「系统分为 后端/前端/插件」三分法对齐。
- 代价：数据驱动限制了复杂逻辑插件（v1 接受，`kind` 预留扩展）。
