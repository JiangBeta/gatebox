# ADR-026：Docker label 反代协议修订（site 地址 + 映射端口 + 片段引用）

- 状态：已接受
- 日期：2026-09-09
- 修订：ADR-007（保持命名空间）、ADR-016（保持宿主端口寻址）、ADR-019（推翻其「高级子 label 忽略/恒 https-443」界定）

## 背景

用户确定以 lucaslorentz/caddy-docker-proxy 为参照，完善「容器 → 编排 → label」的反代能力，要求三点：

1. 指定访问的域名、协议、访问端口；
2. 指定映射端口（反代目标）；
3. 指定 Caddy 片段（网关 → Caddy 片段）。

现状（ADR-019）：派生恒 `https/443`、upstream 恒取首个宿主映射端口、`caddy.*` 高级子 label 一律后置忽略、无片段引用通道。需修订以满足上述能力，同时保持「Form 优先 + Edit 逃生舱」的产品形态。

## 决策

### 1. 域名/协议/访问端口：编码进 site 地址

`caddy` / `caddy_N` 的 label 值为站点地址（可逗号分隔多个站点）：

| 值 | 协议 | 访问端口 |
|---|---|---|
| `example.com` | https（默认） | 443 |
| `http://example.com` | http | 80 |
| `example.com:8443` | https | 8443 |
| `http://example.com:8080` | http | 8080 |

- 首个 `caddy` 无后缀、后续 `caddy_1`/`caddy_2`…（保持前端既有序列化约定）。
- site 地址**不支持路径**（`/path`）；路径表达走逃生舱 `caddy.handle_path`/`caddy.rewrite`（caddy-docker-proxy 官方风格）。派生 `ProxyDomain` 无路径字段。
- 通配符域名（`*.example.com`）原样透传（RootDomain 自动匹配时按后缀）。

### 2. 映射端口：行级绑定，三级优先（ADR-016 寻址不变）

**派生粒度修订（2026-09-09）**：**每个站点（域名行）派生一个独立 Service**——同一容器可经不同域名发布不同端口/不同片段的服务（如 `api.x` 反代容器内 8080 + Basic Auth，`web.x` 反代容器内 8081 + Gzip）。

反代目标仍为 `127.0.0.1:<宿主映射端口>`。每个站点独立解析，**行级覆盖继承服务级**：

1. `caddy_N.reverse_proxy: "{{upstreams [https] [N]}}"`（行级，作用于站点 N）—— 自解释：`N`=容器内部端口，反向查宿主映射；无 `N` 用唯一宿主端口；多宿主端口又无标注 → 不可代理并告警；带 `https` → `UpstreamProto=https`（生成 `transport http { tls }`）。
2. `caddy.reverse_proxy: "{{upstreams [https] [N]}}"`（服务级共享 = 站点 0 默认，其余站点继承）—— 旧「多域名共享同反代」label 继续兼容。
3. `gatebox.upstream_port: <宿主端口>`（服务级逃生舱，全部站点继承）。
4. 省略 → 唯一宿主端口；多宿主端口无可代理并告警。

站点级 `caddy_N.reverse_proxy` 值**不含** `{{upstreams}}` 模板时，该站点整条作为**透传指令**写入该 site block（逃生舱场景），此时该站点不生成受控反代。

### 3. 片段引用：`gatebox.fragments[_N]`

- `gatebox.fragments: name1,name2` → 站点 0；`gatebox.fragments_N` → 站点 N（**行级覆盖**）。每个站点解析为自己的片段集。
- 按 `Fragment.Name` 解析为 ID。
- **默认启用片段自动注入**每个派生站点（与 manual Service 的 `seedDefaultFragments` preselect 行为一致）；上游 https 时自动附加 `frag-skip-verify`（对齐 manual）。
- 引用缺失/片段被删除 → **忽略缺失项 + 派生告警**，站点仍可代理；删除片段不扫描容器（温和降级）。

### 4. 透传逃生舱（`caddy.*` 子指令）

除 `caddy`、`caddy_N`、`caddy[.N].reverse_proxy` 外的 `caddy.X`（含点号嵌套、`N_` 排序前缀）按 caddy-docker-proxy 规则展开为 site block 指令块，作为服务级指令继承到每个派生站点：

```
caddy.handle.0_reverse_proxy: {{upstreams}}
↓  handle {
	    reverse_proxy ...
    }
```

- 全局级键（`caddy.email` / `caddy.admin` / `caddy.http_port` / `caddy.https_port` / `caddy.log` 等）**忽略 + 告警**，不进 Caddyfile 全局块（全局配置归网关页管理）。
- 未知 `gatebox.*` 键忽略（保留兼容）。

### 5. 推导的 site block 拼装

片段内联块 → 透传 `caddy.*` 指令块 → 受控反代/静态段（仅当无该站点 `reverse_proxy` 时生成）。冲突由 `caddy validate` 前置校验拦截回退（ADR-002）。

### 6. 受管根域闭环

派生时把完整域名与已登记 `domains` 列表做**最长后缀匹配**：命中则拆出 `Subdomain + RootDomain` → 自动进入 ddns 上报与 acme 证书签发闭环；未命中保持 `RootDomain=""`（不阻断代理，仅无证书/DDNS）。

### 7. 数据流与触发器

“获取运行中容器 label → 发送给 caddy api” = 现有聚合派生管线（`proxyableContainers → derive → generate → validate → POST /load → 落盘 + ddns`），新增触发：

- 编排动作（部署成功 / down / restart / adopt / convert / upgrade）后自动同步一次；
- docker 页「同步到网关」手动按钮 → `POST /api/v1/docker/sync-caddy`。

## 后果

- 优点：caddy-docker-proxy 存量容器（`caddy` + `caddy.reverse_proxy: "{{upstreams 80}}"`）零改动迁移；Form ⇄ YAML 双向无损往返；片段/证书/DDNS 全部打通。
- 代价：`derive.go` 重写（按站点派生独立 Service + 行级覆盖）、`models.Service` 增加 `ExtraDirectives`（derived-only，不落库）、`caddyfile.go` writeSiteBlock 分站拼装、`compose.ts` 往返扩展、ComposeEditorModal 域名访问区重做（指向端口/片段下沉到每行）、sync-caddy 接口。
