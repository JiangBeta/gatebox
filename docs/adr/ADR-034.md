# ADR-034：服务运行身份与 Docker 权限授予

- 状态：已接受
- 日期：2026-09-15
- 前置：ADR-011（运行时目录与工具安装归属）、ADR-030（核心/插件分类与运行时目录）
- 参考：systemd `User=`/`SupplementaryGroups=`、polkit `rules.d`、Docker Engine 安全说明（`docker.sock` 等价 root）

## 背景

GateBox 需要：① 访问 Docker API（管理容器）；② 在「扩展」页对组件提供重启能力。因此安装期必须把这两件事所需的权限授予到位。

现状与矛盾：

- `scripts/install.sh` 以 root 安装，但 `configs/services/gatebox.service` **没有 `User=`，实际以 root 运行**——与部署设计「专用低权用户 `gatebox`（非 root）」相矛盾（`docs/deploy.md` §3）。
- `docker` 组只授予 **API 访问**；**重启守护进程**（`systemctl restart docker`）需要 systemd 管理权限，`docker` 组给不了。
- 「重启」语义未区分：Docker 的 `reload`（`SIGHUP`，不中断容器）与 `restart`（中断全部容器）风险差异巨大。

## 决策

### 1. 服务身份：专用低权用户 `gatebox`

- 安装脚本创建系统用户 `gatebox`（`--system`、`nologin`、`home=$DATA_DIR`），`$DATA_DIR` 归其所有。
- `gatebox.service` 显式声明 `User=gatebox`、`Group=gatebox`。
- 托管进程（ddns-go / mosdns / flame）由 `gatebox` 拉起，天然同权限，无需额外授权。

### 2. Docker 权限分两层授予

| 层 | 用途 | 授予方式 |
|---|---|---|
| API 访问 | 读写 `docker.sock`（容器/镜像/网络/卷） | 服务用户加入 socket **属组**（安装时 `stat -c %G /var/run/docker.sock` 探测，写入 unit `SupplementaryGroups=`） |
| 守护进程管理 | `docker.service` 的 reload / restart | systemd → **polkit 规则**；OpenRC/procd → **sudoers 白名单** |

### 3. 授权机制

- **systemd（首选）**：安装写入 `/etc/polkit-1/rules.d/49-gatebox-docker.rules`，仅允许用户 `gatebox` 对 `docker.service` 执行 `org.freedesktop.systemd1.manage-units`。走 D-Bus，无需 `sudo`。
- **OpenRC / procd（回退）**：存在 `sudo` 时写 `/etc/sudoers.d/gatebox` 白名单（`sudo -n` 包裹具体 init 命令）；无 `sudo` 则明确提示「重启系统服务需以 root 运行」。
- 仅授权 `docker.service` 单个 unit，不做宽泛授权。

### 4. 重启语义：软/硬两级

| 级别 | 行为 | 场景 | 风险 |
|---|---|---|---|
| **软重启（默认）** | Docker：`systemctl reload docker.service`（`ExecReload=kill -HUP`）；Caddy：Admin API `POST /load`；托管进程：stop+start；acme.sh：重探测 | 应用配置变更 | 不中断容器 |
| **硬重启（显式）** | Docker：`systemctl restart docker.service` | 守护进程异常恢复 | **中断所有容器**，UI 必须二次确认 |

- UI：重启图标默认走软重启；Docker 额外提供「强制重启」入口并确认。
- acme.sh 是 CLI 无守护进程，重启 = 重新探测（返回成功）。

### 5. 服务管理器抽象

- 新增 `backend/internal/adapter/service`：启动探测 init（`systemctl` / `rc-service` / `/etc/init.d`），提供 `Reload(unit)`、`Restart(unit)`。
- 非 root 时自动 `sudo -n`（OpenRC/procd）；权限不足返回语义化错误 `NO_PRIVILEGE`，由 UI 提示。
- `component.Descriptor` 增加 `serviceUnit`（docker = `docker`）；`Restart` / `RestartForce` 按 `reloadURL → serviceUnit → runnable → 重探测` 分派。

### 6. 安装 / 卸载

- `install.sh`：建用户 → 探测 socket 属组 → 写 unit（User/Group/SupplementaryGroups）→ 写 polkit 或 sudoers → 启服务。
- `install.sh --uninstall`：清理 polkit 规则、sudoers、unit、用户；**保留 `$DATA_DIR` 与 `conf/`**。

### 7. 安全声明

- **可写 `docker.sock` ≈ 宿主机 root**，是 GateBox「管理容器」定位的固有权限，安装期须向用户明示。
- polkit/sudoers 授权严格限定到 `docker.service`。
- GateBox 自身只写 `$DATA_DIR`；不因该决策扩大写权限范围。

## 范围与例外

- **NixOS**：`/etc` 由 Nix 管理，install.sh 写 polkit 规则会被 `nixos-rebuild` 覆盖；NixOS 应以 **NixOS module** 声明 unit 与 polkit 规则，**不纳入本次 install.sh 覆盖范围**。
- **polkit 兼容**：仅支持 JS `rules.d`（polkit ≥ 0.106）；老系统 `.pkla` 不兼容，列为尽力支持。
- **无 systemd 且无 sudo**：硬重启降级为「重探测」或要求以 root 运行。

## 后果

- 优点：GateBox 以低权用户即可管理 Docker 生命周期；软/硬重启语义与风险明确；授权最小化。
- 代价：`install.sh` 复杂度上升（多 init 分支 + polkit/sudoers + 卸载清理）；需同步 unit 模板、`docs/deploy.md`、`docs/architecture.md` §11 与术语表。
