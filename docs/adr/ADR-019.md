# ADR-019：网关数据模型细化与跨单位联动

- 状态：已接受
- 日期：2026-08-31

## 背景

在 ADR-018 定下「两层落库真相 + docker 派生视图」后，需进一步定 ProxyRoute 的落库字段、域名与 Domain 单位的联动方式、file_server 的 root 来源、以及 docker 自动派生的映射规则。本轮 grilling 就这四项作出决策。

## 决策

1. **ProxyRoute 落库字段**（仅 `source = manual` 落库）：

   | 字段 | 类型 | 说明 |
   |---|---|---|
   | `id` | string | 随机 ID（落库主键） |
   | `appId` | string | 外键 → App；**App 表暂不建，本字段留空占位**（「一个 App 多 route」真实需求出现再拆） |
   | `name` | string | 列表「名称」 |
   | `description` | string | 悬停显示的「说明」 |
   | `host` | string | 完整域名 |
   | `port` | int | 访问端口（80/443/自定义） |
   | `type` | enum | `reverse_proxy` / `file_server` |
   | `upstream` | array | 后端 `地址:端口`（反代用；本期单元素，数组化向后兼容） |
   | `root` | string | 静态根目录（file_server 用） |
   | `enabled` | bool | 停用/启用（对应「停止」操作） |
   | `handlerIds` | []string | 引用的 Handler 实例 id |
   | `createdAt` | time | 创建时间 |

   健康检查参数（`health_uri` 等）不在此表，属反代子问题、另行决策。

2. **域名联动（Domain 单位）**：主路径**选已登记 rootDomain + 填子域**（取 DNSCredential → DNS-01 → ddnsgo 上报，对齐 `domain.md` §4）；保留「自由填完整域名」高级项（不校验、不联动 DNS，无凭证时走 HTTP-01 或不签证书）。

3. **file_server 的 root**：用户填**宿主机绝对路径**，不内置上传/文件管理（后置）；目录不存在时提供「自动创建空目录」。

4. **Docker 自动派生映射**：
   - **名称** = `displayName`（有则用）+ `service` 拼接；`GET /docker/proxyable` 需补 `displayName` 字段（当前只返回 `Project/Service/ContainerName/HostPort/Labels/State`）。
   - **说明** = `gatebox.description` label，没有则空。
   - **domain 不强制** rootDomain 校验（消费用户已写的 label，拦截会破坏 ADR-007「零改动迁移」）；UI 仅提示「未登记 rootDomain 无法 DNS-01」。
   - **后端地址端口** = `127.0.0.1:HostPort`（ADR-016）；本期只消费 `caddy`/`caddy_N` 的 domain 部分 + `HostPort`，`caddy.reverse_proxy` 等高级子 label **后置**（先透传忽略）。

## 后果

- 优点：手动 route 字段最小且向后兼容（upstream 数组化）；「一个 App 多 route」可平滑演进而不提前造表；Docker 自动保持「零改动迁移」。
- 代价：`/docker/proxyable` 需补 `displayName`（跨单位接口的小改动）；自由填域名的 route 不参与 DNS-01 自动化，需 UI 明示。
- 约束：file_server 不负责文件内容，用户须自管目录；`caddy.reverse_proxy` 等高级 label 本期静默忽略，需在文档标注以免误以为已支持。
