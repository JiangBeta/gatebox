# ADR-023：外部组件扩展——flame / mosdns / tailscale 接入边界

- 状态：已接受（接入深度部分待讨论）
- 日期：2026-09-07
- 前置：ADR-001（控制面 + 独立外部组件）、ADR-013（acme.sh）

## 背景

PRD v2（2026-09「缝合怪」重构）在原有 caddy / acme.sh / docker / docker-compose / ddns-go 之外，新增三个外部组件：**flame（导航）**、**mosdns（内网 DNS）**、**tailscale（组网）**。需明确各自接入边界，守住 ADR-001「不接管外部组件生命周期」。

## 决策

1. **flame（导航）＝单二进制进程 + 页面内嵌展示**：
   - 运行形态：**单二进制**（本机 `tools/flare-<arch>`），由系统服务管理器拉起；默认端口 5005。
   - GateBox 只做「部署初始化（配置文件 / 运行目录）+ 内嵌 iframe 展示（`flame_url`）+ 已发布应用 → 导航项的配置联动」；**不实现导航页渲染逻辑**。
   - 页面内嵌决策：首页「导航」Tab 内嵌 flame 页面（用户已拍板）。
2. **mosdns（内网 DNS）＝配置改写 + 重启**：
   - 目标：网关发布应用后，内网解析记录自动指向对应 LAN IP（`tools/mosdns/` 配置 hosts 段），与 ddns-go 公网上报**双轨**。
   - 接入深度（仅引导+状态 vs 完全接管改写配置）**待讨论**（决策点 D1，见 `docs/network.md`）。
3. **tailscale（组网）＝CLI 状态 + 有限操作**：
   - GateBox 调 `tailscale` CLI（`status --json` 等）只读为主；up/down/退出等操作视 D1 深度决定。
   - **不代持登录**（`tailscale up` 为交互式凭据流程）。
4. **容器 → 网关代理数据「实时」**（docker events 流，联动 docker.md §12.3）：由 Docker 单位负责订阅并推送内存事件，网关据此刷新派生列表；**自动 `/load` 仅限 GateBox 主动操作触发**，外部 docker 变化不自动覆盖 Caddyfile。

## 后果

- 优点：新增能力保持「控制面只读写配置」原则，无生命周期接管；flame 以单二进制出现更轻（比 docker 版更省内存）。
- 代价：flame/flare 的配置落点与 API 需研究（联动实现，见 `docs/home.md` §6 F2）；mosdns 分流策略不接管（只写 hosts 段）。
- 约束：D1（mosdns/tailscale 深度）与 F2（导航联动实现）未定前对应功能保持「状态 + 手动触发」占位。
