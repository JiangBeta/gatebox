# ADR-033：Caddy 内置片段的功能与边界定案

- 状态：已接受
- 日期：2026-09-15

## 背景

ADR-018 修订 Q7 定下「8 个只读内置 Caddy 片段」清单（Gzip/Br、Basic Auth、忽略自带证书校验、健康检查、日志配置、阻止常见漏洞、静态资源缓存、支持 websocket），但落地 code 多与需求不符，且存在会导致 Caddy 配置加载失败的严重缺陷：

- `frag-skip-verify` 的 code（`tls_connection_policies {...}` + `reverse_proxy { ... }`）不是合法的 site block 指令，`caddy validate` 直接失败；而它又在「后端协议 = https」时被强制写入 `FragmentIDs`，导致**所有 https 上游服务/派生站点的配置加载失败**。
- 「忽略证书校验」真正生效点应是 `transport http { tls_insecure_skip_verify }`；原 `transport http { tls }` 仅启用 TLS、并不跳过校验（官方文档核实）。
- `frag-healthcheck`、`frag-websocket` code 为空；`frag-static-cache` 名为长缓存但 code 为 `Cache-Control no-cache`；`frag-gzip` 描述含标准版不支持的 brotli；`frag-log-config` 的 `level debug` 对 access log 无效且与全局日志重复。

本轮 grilling 逐条定其功能与边界，并落地 code。

## 决策

### 1. 片段作用域 = code 自描述（不新增模型字段）

片段 code 首个非空行的首个 token 决定其归属：

| 片段 code 形态 | 生成器处理 |
|---|---|
| 顶层指令（`encode` / `header` / `basic_auth` / `log` / matcher + `respond` …） | 原样写入 site block 顶层 |
| `reverse_proxy { <子指令> }`（**不带参数**） | 抽取内部行，**合并**进生成器产出的 `reverse_proxy {}` 块 |
| `reverse_proxy` 带参数（上游/matcher） | 生成**报错**（上游由 Service 决定，防双真相源） |
| 同一片段既含顶层指令又含 `reverse_proxy {}` | 生成**报错** |

去重规则：生成器默认注入的 https `transport http { tls }` 在**任一片段已提供 `transport`** 时让位（片段优先）。多个 `reverse_proxy` 包裹片段按 ID 字典序合并内部行。

非反向代理服务（静态文件）上出现 `reverse_proxy` 包裹片段时**静默跳过**：默认启用片段由 `seedDefaultFragments` 按类型无关方式 seed，生成器对不适用类型直接忽略，避免误报阻断生成。

### 2. 内置目录：8 → 7 片段 + 1 字段

| 片段 | 形态 | 默认启用 | 默认隐藏 | code / 说明 |
|---|---|---|---|---|
| `frag-gzip` | site | ✅ | | `encode zstd gzip`（标准版无 brotli，改名 Gzip/Zstd） |
| `frag-basic-auth` | site | | ✅ | `basic_auth { admin <bcrypt(admin)> }`；默认 admin/admin，待「设置-用户」完善后改用用户库 |
| `frag-skip-verify` | reverse_proxy 包裹 | | ✅ | `reverse_proxy { transport http { tls_insecure_skip_verify } }`；仅后端协议 = https 时由生成器条件应用 |
| `frag-log-config` | site | ✅ | | 每服务独立日志：`log { output file <%GB_LOG_FILE%> … }` |
| `frag-block-common` | site | ✅ | | 安全响应头 + `@gb_blocked method TRACE TRACK` + `respond 405` |
| `frag-static-cache` | site | | | 静态扩展名 matcher + `Cache-Control public, max-age=2592000`（30 天） |
| `frag-websocket` | reverse_proxy 包裹 | ✅ | | `reverse_proxy { flush_interval -1 }`（WebSocket/SSE 流式优化） |

- **移除「健康检查」内置片段**：健康检查是 `reverse_proxy` 内部指令（`health_uri`），改由 `Service.HealthURI` 字段承载（默认 `/`，可编辑/关闭，ADR-020 §1），避免与片段双真相源。
- `frag-skip-verify` 不再写入 `Service.FragmentIDs`，改由生成器在所有片段解析前按 `UpstreamProto == "https"` 条件应用，修复「上游协议变更后残留」问题。

### 3. 变量接线

**最小变量集**（唯一物理路径原语 + 服务上下文）与其组合定义：

| 变量 | 值 | 类型 |
|---|---|---|
| `<%GB_APP%>` / `<%GB_SERVICE%>` / `<%GB_HOST_PORT%>` | 运行时按服务上下文解析 | 最小 |
| `<%GB_DATA_DIR%>` | 实际 `data_dir` 绝对路径 | 最小（路径原语） |
| `<%GB_STATIC_ROOT%>` | `<%GB_DATA_DIR%>/www`（默认；自定义 `static_root` 时显示实际值） | 组合 |
| `<%GB_LOG_FILE%>` | `<%GB_DATA_DIR%>/logs/caddy/<%GB_APP%>_<%GB_SERVICE%>.log` | 组合 |

- **系统变量统一由后端下发**：`GET /api/v1/gateway/variables/system` 返回 `[{key,value,description}]`，物理路径解析为实际值、服务上下文保留 `<%…%>` 占位；「变量」页只读展示（替换原前端硬编码 `(运行时填充)`）。
- `<%GB_STATIC_ROOT%>`：新增 conf 项 `static_root`（默认 `<dataDir>/www`，env `GATEBOX_STATIC_ROOT`），生成器注入；静态服务默认 root 取 `<%GB_STATIC_ROOT%>/<%GB_APP%>/`。
- `<%GB_LOG_FILE%>`：生成器按 `<dataDir>/logs/caddy/<应用>_<服务>.log` 计算并注入（应用/服务名做 `[A-Za-z0-9._-]` 清洗，空应用名回落 `default`）。
- 全局 access log 迁移到 `<dataDir>/logs/caddy/access.log`（原 `tools/caddy/logs/access.log`）。网关「服务日志」优先读每服务独立文件，缺失时回落全局日志 + host 过滤。
- 修正文档表述：Caddy 环境变量占位符为 `{$VAR}`（可带默认 `{$VAR:default}`），`${...}` 并非 Caddy 语法。

### 4. 默认启用/隐藏的驱动

- 后端 `seedDefaultFragments` 维持类型无关（默认启用片段对全部服务 seed）；生成器按类型丢弃不适用片段。
- 前端「其他选项」改为读取后端 `defaultHidden` 过滤，删除硬编码隐藏集合（`frag-healthcheck`/`frag-skip-verify`）。
- 内置片段在片段管理抽屉中禁止编辑 code（只读，与「内容不可修改」提示一致）。

## 后果

- **修复缺陷**：https 上游服务不再因非法 `frag-skip-verify` code 导致 Caddy 配置加载失败；「忽略证书校验」真正生效。
- 内置条目中「健康检查」退出片段目录、回归 Service 字段；`skip-verify`/`websocket` 转为 `reverse_proxy` 包裹片段。
- 每服务默认产生独立访问日志文件；全局 `access.log` 迁移路径。
- 需同步 `docs/gateway.md`、`docs/glossary.md`、`docs/PRD.md` 中旧「8 条目/内置清单」表述，并清理 glossary 中已废弃的 `handlerIds` 术语。
