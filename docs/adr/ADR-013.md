# ADR-013：证书管理——独立 acme.sh(DNS-01) + 抽象层

- 状态：已修订（替代原「Caddy ACME」决策）
- 原日期：2026-08-21
- 修订日期：2026-09-03

## 背景

域名功能涉及证书签发。原 ADR-006 / 013 定「Caddy ACME 自动、代理即签证、无独立证书管理」。实际运行中发现：**标准版 Caddy 二进制（v2.11.x）不含 DNS provider 插件**（caddy-dns/dnspod 等仍基于 libdns v0.2，与 Caddy 引入的 libdns v1 不兼容，上游未修），导致 `tls { dns dnspod ... }` 指令 `module not registered`。IPv6/内网环境走 HTTP-01 亦不适用。

**新决策：证书 DNS-01 签发交给独立 acme.sh（外部组件），Caddy 仅按文件加载证书。**

## 决策

1. **证书执行者：独立 acme.sh（Let's Encrypt，DNS-01）**。GateBox 在 reloadCaddy 时对每个 HTTPS 域名行且已登记 DNS 凭证的 host 调 acme.sh 签发：
   - `acme.sh --issue --dns dns_dp -d <fqdn> --keylength ec-256 --server letsencrypt`
   - provider 映射：dnspod→`dns_dp`(DP_Id/DP_Key)、cloudflare→`dns_cf`(CF_Token)、aliyun→`dns_ali`(ALI_KEY/ALI_SECRET)。
2. **证书落盘**：`<DATA_DIR>/tools/acme/certs/<fqdn>/{fullchain.pem, key.pem}`。**caddy 侧只渲染 `tls <fullchain> <key>` 引用文件**，不再内嵌 DNS 插件。
3. **签发失败不阻塞控制面**：某个 host 证书缺失/签发失败时，reloadCaddy 仅告警并继续；该 site block **不渲染 tls 指令**（避免 caddy load 因文件缺失整体失败），交由 caddy 默认行为；其余域名与服务（含停/删）不受影响。
4. **证书粒度：每二级域名一张证书**；概览按 rootDomain 聚合展示最坏状态（有已过期标红、有快过期标黄、全未申请标未申请、否则成功）。
5. **证书管理器抽象**：证书访问走「证书管理器」接口（当前实现 = `AcmeCertManager` 读 acme.sh 证书目录），未来切 CA/客户端只换实现。
6. **CA 与续期**：默认 Let's Encrypt；acme.sh 证书仍有效时自动跳过重签（避免命中速率限制）；续期由 acme.sh 自身 cron 或管理员定时 `acme.sh --cron` 完成。

## 后果

- 优点：Caddy 保持官方标准版（无需 xcaddy 重编带插件）；证书 DNS-01 可在纯内网环境签发（公网 DNS 可达即可）；签发失败局部化。
- 代价：
  - 引入 acme.sh 外部依赖：`GATEBOX_ACME_BIN`（默认 PATH 中 `acme.sh`）。
  - DNS 凭证必须对目标 rootDomain 有**增删 TXT 记录权限**；凭证失效时该域名证书无法续签。
  - acme.sh 的家目录默认 `~/.acme.sh`（ACCOUNT/域名密钥均存此）。
- **仍不提供**（后续补）：手动重新申请、私钥复用 / 下载、申请历史、多 CA 选择界面。

## 迁移注意（既有部署）

- 旧部署若用过 Caddy ACME 证书（`<DATA_DIR>/tools/caddy/data/caddy/certificates/`），本次改为读 acme 目录后，证书列表将按 acme.sh 产物显示；旧证书不再被管理。
- 需确认 acme.sh 已安装且对应用户与后端进程同 PATH；启动后端需带 `GATEBOX_ACME_BIN` 或确保 `acme.sh` 在 PATH。
