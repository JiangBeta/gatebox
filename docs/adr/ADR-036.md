# ADR-036：扩展平台（扩展点、能力注册表、投影契约与 appstore 数据模型）

- 状态：已接受
- 日期：2026-09-15
- 前置：ADR-027（生命周期边界）、ADR-028（组件运行时接口）、ADR-029（插件模型与分发）、ADR-030（核心/插件分类）
- 取代：ADR-029 第 1 条中「v1 不引入解释器/子进程协议」的运行时限制（数据模型层保留并升级）

## 背景

ADR-029 的插件模型是「manifest 数据 + 通用引擎 + 三种 kind」，核心与插件本应无关。但实际编码中，**能力型插件已经渗入核心功能**：

- `handler/gateway_api.go` 判断配置是否含 `layer4 {` 并挑选 `caddy-l4` 制品做校验（`caddyL4Bin`）；
- `handler/gateway_ports.go` 把非 HTTP 协议硬编码为 `caddy.L4Binding`；
- `adapter/caddy/caddyfile.go` 内置 `layer4` 文本生成（`collectL4Servers`）；
- 前端 `AppFormModal.vue` / `ComposeEditorModal.vue` 直接判断 `p.id === 'caddy-l4'`；
- ddns 二级域名联动由核心直接调用 `ddns.Manager`。

这违背「核心功能与插件编码无关」的目标。同时，未来的 appstore 需要：在线获取插件信息、安装时同时下发**后端制品与前端页面代码**、以及插件自身的**后端逻辑**。需要在**不改动核心功能**的前提下建立统一扩展机制。

本 ADR 把 ADR-029 的「三种 kind」升级为**五个部件 + 两类贡献原型**，核心只认扩展点，不认插件身份。

## 决策

### 1. 三个不变式（地基）

- **I1 核心无插件身份**：核心代码不得出现任何插件 ID 或插件专有术语（`caddy-l4` / `layer4` / `coraza` …），只认抽象扩展点。
- **I2 核心 → 插件**：只经**投影 API**（只读、scoped、带 revision）。
- **I3 插件 → 核心**：只经**贡献声明**（manifest 静态注册）+ 契约调用；插件不读核心数据库、不触碰核心前端 store/DOM。

### 2. 五个部件

| 部件 | 职责 |
|---|---|
| **Manifest v2** | 强类型：`artifacts[]`（带 role）、`contributes{capabilities,ui,backend,data}`、`permissions` |
| **能力注册表 Capability Registry** | 核心与插件统一注册「能力」；消费者（网关/容器/前端）只查表 |
| **投影 API Projection API** | 核心状态只读视图（domains/certs/ports/services）+ `revision` + 变更通知 |
| **扩展契约 Extension Contract** | 核心调用插件逻辑的两种实现：`template`（声明式）或 `sidecar`（进程，JSON over stdin/HTTP） |
| **槽位/页面注册表 Slot/Page Registry** | 前端具名合并点 + 页面/路由 + 三档渲染 |

### 3. 两类贡献原型（由贡献点导出，非硬编码）

| 原型 | 用到的贡献点 | 作用 | 例 |
|---|---|---|---|
| **Provider（能力型）** | `capabilities` + `backend.renderer` + `ui.slots` | 扩展核心行为 | Caddy-L4 |
| **Consumer（数据型）** | `data.subscribe` + `backend.reconcile` / `backend.config-sync` + `ui.page` | 消费核心数据、作用于外部 | ddns-go |

同一插件可兼具两者；核心对二者无区分性代码。

### 4. 扩展点契约（point）

| point | 语义 | 关键字段 |
|---|---|---|
| `proxy-protocols` | 可代理的协议类别 | `class`(http\|non-http)、`label`、`networks`、`requiresPrimaryDomain` |
| `renderer` | 给定中性规则生成 Caddyfile 片段 | `for`(class/协议)、`scope`(global\|site)、`impl`(template\|sidecar) |
| `validator` | 校验器（可声明用哪个制品跑 `caddy validate`） | `bin`（缺省 = 当前 active caddy 制品） |
| `config-sync` | 从投影渲染插件配置并落盘 + reload | `projection`、`target`、`template`、`reload` |
| `reconcile` | 核心通知侧车，由侧车拉投影自行收敛 | `entry`、`projection`、`interval` |

核心内置能力注册为 `_core` provider（http/https 协议 + HTTP site 渲染器），与插件**同构**。

### 5. 中性规则与渲染分发

核心只定义中性模型：

```go
type ProxyRule struct {
    Protocol string   // 协议名，如 https / mqtt
    Upstream string   // 后端地址:端口
    Ports    []int    // 监听端口（端口页登记）
    Nets     []string // tcp / udp
}
```

生成器流程：HTTP 规则走内置渲染器（site block）；非 HTTP 规则按协议查注册表 → 调用其 renderer → 得到全局块片段 → 写入全局块。**核心不解析片段内容，也不认识 `layer4`。**

### 6. 投影与调和（level-triggered）

- 投影端点：`/api/v1/extensions/me/projection/{domains,certs,ports,services}`，带单调递增 `revision`。
- 变化时核心更新 `revision` 并**变更通知**（webhook push + long-poll 兜底）；通知不含业务语义。
- 插件拉**全量期望态**自行 diff 收敛：幂等、可自愈、无漏事件问题。
- 插件身份：安装时生成 plugin token，绑定 manifest `permissions.api` 声明的 scope（如 `domain:read`）。插件不共享管理员 session。
- 密钥：凭证属插件配置，存 GateBox 加密库（`conf/secret.key`），经 env/0600 文件注入，**不进投影**。

### 7. 前端渲染三档

| 层 | 形态 | 隔离 | 适用 |
|---|---|---|---|
| L0 元数据驱动 | 核心按 slot/schema 渲染 | — | L4 协议选项、ddns 表单（必做） |
| L1 iframe + postMessage 桥 | 强隔离 | 外部组件自带 UI、未受信插件（本阶段做） |
| L2 远程 ESM 组件 | 无（同源=等价 XSS） | 仅 official/verified（预留，按信任级门禁） |

铁律：**插件 UI 与核心的唯一通道是 API / postMessage 桥**。

### 8. appstore 数据模型

**Manifest v2**

```yaml
apiVersion: gatebox/v2
id: caddy-l4
kind: caddy-module            # process | caddy-module | config-only
version: 0.1.0
publisher: { id, name, keyID }
requires: { gatebox, extensionApi, components: [caddy], os, arch }
artifacts:                    # 带 role 的列表
  - { role: binary, os: linux, arch: amd64, url, sha256, size,
      install: { to: tools/caddy-l4/caddy-l4, mode: "0755" } }
  - { role: ui, format: esm, url, sha256, entry: index.js }
contributions:
  capabilities:
    - point: proxy-protocols
      data: { class: non-http, label: "TCP/UDP", networks: [tcp, udp], requiresPrimaryDomain: false }
  backend:
    - point: renderer
      for: non-http
      scope: global
      impl: { type: template, template: "layer4 {\n{{ range .Rules }}...{{ end }}\n}" }
  ui:
    slots:
      - { slot: port-form.protocol-options, from: proxy-protocols }
permissions:
  - { filesystem: { write: [tools/caddy-l4] } }
  - { api: [gateway:read] }
```

**Catalog（index.json，静态托管）**

```json
{ "schema": "gatebox.catalog/v1",
  "publisher": { "id": "...", "keyID": "..." },
  "plugins": [
    { "id": "caddy-l4",
      "versions": [
        { "version": "0.1.0", "channel": "stable", "publishedAt": "...",
          "manifest": {}, "artifacts": [], "signature": "..." } ] } ] }
```

**本地状态（BoltDB `plugins`）**：`artifacts[]` / `permissions` / `capabilities` / `config`。

**制品 role**：`binary` | `sidecar` | `ui` | `assets`。

**包格式**：单一签名 tar.gz（manifest + 多 role 制品）；制品亦可走独立 URL。

**信任分级**：`official | verified | community`，决定可用 UI 层与权限。

**权限**：`filesystem` / `network` / `api(scope)`。

### 9. 运行时与隔离

- 侧车与 GateBox 同用户同权限（ADR-034）；cgroup/命名空间隔离后置。
- 生命周期状态机沿用 ADR-029（available → installed → enabled/disabled，失败转 error）。

## 本阶段实现边界

**实现**：能力注册表、Manifest v2 强类型、`template` 渲染器、投影 API、L0/L1 UI、ddns 走 `config-sync` 契约；移除核心中 `caddy-l4`/`layer4` 硬编码。

**预留不实现**：`sidecar` 运行时、L2 远程 ESM、签名校验、在线索引下载、权限授予 UI。

## 后果

- 优点：核心真正与插件解耦；能力型插件（Caddy-L4）零核心改动接入；数据型插件（ddns-go）走统一投影契约；appstore 有完整数据模型。
- 代价：引入能力注册表与投影 API；`template` 表达力有限，复杂逻辑需 sidecar；形式上推翻 ADR-029 的「v1 无子进程」；Manifest 结构由 v1 升级到 v2（需迁移）。
