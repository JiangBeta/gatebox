# ADR-031：后端分层与仓库目录 v3

- 状态：已接受
- 日期：2026-09-14
- 前置：ADR-027 ~ ADR-030
- 参考：go-nunu（MIT，分层词汇）、Vue Admin 四层规范（前端，见 ADR-032）

## 背景

现有后端为「每个外部组件一个 `internal` 包 + `main.go` 手工装配」，无统一分层；面对组件运行时与插件扩展，需要一套「不需要讨论就能定位代码」的标准。同时决定「全量重写 vs 渐进迁移」与旧代码处置。

## 决策

### 1. 采用分层骨架（借词汇，不引依赖）

```
backend/
├── cmd/gatebox/main.go
└── internal/
    ├── server/      # 路由 + 中间件（装配）
    ├── handler/     # HTTP 翻译层
    ├── service/     # 用例编排层
    ├── repository/  # BoltDB 持久化
    ├── model/       # 领域实体（依赖为零）
    ├── component/   # 组件运行时（接口+注册表+生命周期引擎）
    ├── plugin/      # 插件引擎（manifest + 三形态）
    ├── source/      # 制品源（索引/签名/下载/版本）
    ├── adapter/     # 外部系统适配（caddy/docker/acme/ddns/mosdns/systemd）
    ├── gateway/     # 领域：Caddyfile 生成 + label 派生
    ├── config/ web/ pkg/
```

- 骨架基准为 [go-nunu](https://github.com/go-nunu/nunu)（MIT）的分层词汇；**不引入 Casbin/RBAC/代码生成器**。
- 唯一判层规则见 `docs/architecture.md` §8.2；依赖方向 `handler → service → {repository, component, source} → model`，由 `golangci-lint depguard` 强制。

### 2. 推进方式：绞杀者渐进式

旧功能逐个迁移，每步可构建/测试/验证；不采用全量重写。

### 3. 旧代码处置

- 原代码**整体保留于 `./old/`**（`old/backend` 带独立 `go.mod`，`old/frontend` 不参与新构建）。
- 根 `go.work` 同时纳入 root module 与 `./old/backend`：旧码可编译、可测试、可查证，不污染新码。

### 4. 代码仓库目录

```
gatebox/
├── go.work
├── backend/ frontend/
├── plugins/                 # 内置插件 manifest + schema + 文档
├── registry/                # 索引模板与 schema（索引本体托管独立仓库）
├── tools/                   # 内置制品存档（离线安装）：tools/<id>/<os>-<arch>/
├── old/                     # 原代码全量
├── docs/ scripts/ configs/
```

## 后果

- 优点：代码定位不再需要讨论；旧实现可回溯；新旧并存零破坏。
- 代价：需要一次性目录重建与 lint 门禁接入（P0）。
