# ADR-030：核心/插件分类与运行时目录

- 状态：已接受
- 日期：2026-09-14
- 前置：ADR-027（生命周期）、ADR-028（运行时接口）

## 背景

需要明确「哪些是核心功能、必须默认安装」与「哪些是插件、可后续安装」；同时需明确二进制在运行时的落点与运行位置（原 `tools/`）。

## 决策

### 1. 分类标准：主闭环必要性

产品主闭环 = 「应用（容器/手工）→ 经域名由 Caddy 反代 → 自动 HTTPS」。

| 组件 | 档 | 生命周期 |
|---|---|---|
| Caddy | core | managed / replace |
| acme.sh | core | managed / replace |
| docker + docker-compose | core | docker=**attached**；compose=managed |
| ddns-go | optional（Bundled） | managed / replace |
| flame | optional（Bundled） | managed / replace |
| mosdns | optional | managed / replace |
| tailscale | optional | managed / replace |
| coraza | optional | caddy-module |

- `core`：默认安装、默认启用、`Removable=false`。
- `optional`：按需安装；`Bundled=true` 随离线包附带但默认停用。
- **正交提醒**：`core` 是产品重要性；`managed/attached` 是生命周期归属。docker = `core + attached`。

### 2. 运行时目录 `$DATA_DIR`

组件与插件的可执行制品**统一落 `$DATA_DIR/tools/<id>/` 并在此运行**，`versions/` 支撑升级与回滚；**不另设运行时 `plugins/` 目录**。

```
$DATA_DIR/
├── conf/
├── tools/
│   ├── caddy/{caddy, versions/<ver>/, user/, logs/, data/}
│   ├── acme/{acme.sh, certs/<fqdn>/}
│   ├── docker-compose/docker-compose
│   ├── ddnsgo/ · mosdns/ · tailscale/ · flame/
│   └── <plugin-id>/
├── appData/<projectName>/
├── Caddyfile
└── README.md
```

### 3. 权限极简（顺带）

单管理员 + 密码哈希 + 登录态中间件；仅定义 `Capability` 常量表预留扩展，**不引入 Casbin/RBAC**。权限「尚未开发」不阻塞本重构。

## 后果

- 优点：核心/插件边界清晰；离线安装（Bundled）与轻量（optional 默认不装）兼顾；制品目录单一，回滚路径明确。
- 代价：`core` 中的 docker 为 attached，需在 UI 明示「由系统管理」。
