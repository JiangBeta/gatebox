# ADR-016：代理寻址与容器稳定标识

- 状态：已接受
- 日期：2026-08-25

## 背景

ADR-007 约定复用 caddy-docker-proxy 的 label 语法，其中 `reverse_proxy` 的值写作 `{{upstreams 8080}}`。但 **GateBox 自行生成 Caddyfile、不安装 caddy-docker-proxy 插件**，因此该模板必须由本工具自己解释成一个具体地址。

关键约束：**caddy 是 `$DATA_DIR/tools/caddy/caddy`——宿主机二进制、systemd 服务，不是容器**。docker 的内嵌 DNS（`127.0.0.11`）只在容器内部可用，宿主机上的 caddy 解析不了 `jellyfin:8096` 这类服务名。故「用服务名寻址」这条路在当前架构下不可行。

同时，`docker compose up` **每次重建容器，容器 ID 与容器 IP 都会变**。

## 决策

### 1. 寻址方式：`127.0.0.1:<宿主机映射端口>`

`{{upstreams N}}` 解释为 GateBox 自动分配的高位宿主机端口，**绑定 `127.0.0.1` 而非 `0.0.0.0`**。容器 IP 直连作为高级选项保留。

| | 容器 IP : 容器端口 | **127.0.0.1 : 映射端口（采用）** |
|---|---|---|
| 对外暴露 | 否 | 否（绑 loopback） |
| 容器重建后 | IP 变，**Caddyfile 必须重新生成** | 不变，无需任何动作 |
| 需要的机制 | 监听 docker events + 自动重生成 + `/load` | 无 |

### 2. 容器稳定标识：`project + service`

App 指向容器用 `com.docker.compose.project` + `com.docker.compose.service` 这一对 label（游离容器回退 `container_name`）。容器 ID 每次重建必变，`container_name` 很多用户不设，唯有这一对永远存在且永不变。

### 3. 跨单位接口

Docker 单位暴露给网关单位的结构**不含容器 ID 与容器 IP**，从接口层面杜绝下游依赖易变值：

```go
type ProxyableContainer struct {
    Project, Service, ContainerName string
    HostPort                        int
    Labels                          map[string]string
    State                           string
}
```

Docker 单位只负责「label ⇄ 表单转换 + 落盘 + 暴露」，**Caddyfile 生成完全归网关单位**。

## 后果

- 优点：**消除「容器重启后网站 502」这一经典故障源**；无需 docker events 监听机制；接口层面防止下游耦合易变值。
- 代价：每个被代理服务占用一个本机高位端口（绑 loopback，不暴露公网）；服务必须显式映射端口。
- 约束：需实现端口自动分配且避免冲突；表单需提供「加入 caddy 网络」开关以支持高级选项下的容器 IP 直连。
