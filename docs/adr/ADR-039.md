# ADR-039：插件运行时契约（sidecar 托管、API 反代、plugin token、UI 宿主与 dns-provider）

- 状态：已接受
- 日期：2026-09-16
- 前置：ADR-028（组件运行时）、ADR-036（扩展平台）、ADR-037（主程序与插件分离）、ADR-038（组件配方变体）
- 取代：ADR-036「本阶段实现边界」中关于 sidecar 运行时、L1 UI、权限授予、在线索引下载的实现时机限制

## 背景

分离之后，插件的后端逻辑与前端页面必须能在**不改动内核**的前提下加载、运行、卸载。ADR-036 定义了契约的形状，但以下全部为「预留未实现」，且现状存在硬缺口：

- sidecar 运行时不存在；扩展契约只实现了 `template`；
- 控制面 API 零鉴权，插件权限 `permissions` 只声明、从不执行；
- 插件 UI 贡献（`ui.nav/routes/slots/page`）已建模但前端零消费，导航与路由硬编码（`toolRoutes.ts`）；
- DNS 凭证供应商散落 **5 处硬编码**（`model/models.go:10`、`handler/api.go:784`、`adapter/acme/acme.go:371`、`adapter/ddns/manager.go:31`、`CredentialFormModal.vue:25`），新增供应商需改 4+ 文件；
- 安装 `acme.sh` 只提取单文件（`source.go:254`），**`dnsapi/` 脚本被丢弃**，干净环境找不到 hook；
- `FetchIndex` 无调用点，在线索引未接线。

## 决策

### 1. sidecar 托管与通信

- `kind:process` 的插件提供一个后端 sidecar 制品；由组件进程托管器统一拉起（复用 `component/process.go` 的 `Setsid` + pid 文件 + SIGTERM→SIGKILL + 日志重定向）；
- sidecar **只监听 `127.0.0.1` 随机端口或 unix socket**，不对外暴露端口；
- 内核反向代理，插件后端不直接面向浏览器。

### 2. API 反代与 plugin token

- 内核统一暴露两条同源路径：
  - UI：`/plugins/<id>/*` → 静态托管插件的 UI 制品；
  - API：`/api/v1/plugins/<id>/*` → 反代到 sidecar。
- 安装时生成 **plugin token**，绑定 manifest `permissions.api` 声明的 scope（如 `domain:read`、`gateway:read`）；
- 核心的投影 API 等内部接口按 token + scope 校验；插件不共享管理员 session；
- `permissions.filesystem.write` 转为**路径白名单**并在内核侧实际强制；`permissions.network` 记录并在安装确认页展示；
- 控制面管理鉴权（单管理员登录）仍为独立议题，但 **plugin token 机制本轮建立**。

### 3. UI 宿主与 postMessage 桥

三档渲染（沿用 ADR-036 §7，本阶段落地 L0/L1）：

| 层 | 形态 | 本阶段 |
|---|---|---|
| L0 元数据驱动 | 内核按 slot / schema 渲染 | 实现（覆盖声明式核心扩展） |
| L1 iframe + postMessage | 插件自带 UI，强隔离 | 实现（覆盖独立进程页面，复用 flame 的 iframe 模式） |
| L2 远程 ESM | 同源，等价 XSS | 后置，仅 `official`/`verified` |

- UI 制品（`role:ui`，`format: iframe`）安装到 `$DATA_DIR/tools/<id>/ui`，内核静态托管于 `/plugins/<id>/`；
- 导航来自 manifest `ui.nav`，内核启动时动态 `router.addRoute`；删除 `utils/toolRoutes.ts` 的硬编码映射；
- **postMessage 桥只承载宿主能力，不传业务数据**，最小消息集：

| 方向 | 消息 | 语义 |
|---|---|---|
| 内核 → 插件 | `init` | 下发 `pluginId`、plugin token、主题、locale |
| 插件 → 内核 | `ready` | UI 就绪 |
| 插件 → 内核 | `resize` | 内容高度变化 |
| 插件 → 内核 | `navigate` | 请求宿主路由跳转 |
| 插件 → 内核 | `toast` | 请求宿主提示 |
| 插件 → 内核 | `setTitle` | 设置当前页标题 |

- 铁律：**插件 UI 与核心的唯一通道是 API / postMessage 桥**；插件不读核心 store、不触碰 DOM、不引入核心模块。

### 4. 分发与发现

- 内核从**磁盘 manifest** 加载插件目录（内置插件随包落盘，不再硬编码 Go 数组）；在线插件从 Store `index.json` 拉取；
- `source.FetchIndex` 接线：拉索引 → 版本比较 → 校验 sha256 → 下载 / 安装 / 升级；
- 签名验签预留（字段保留，本阶段不实现）；索引 URL 可配置，默认指向 `JiangBeta/GateBoxStore`；
- 目录 schema：`catalog.v1`（新增 `variants[]`，见 ADR-038）。

### 5. 新增扩展点：`dns-provider`

让「新增 DNS 凭证供应商」= 安装一个插件，零内核改动：

```yaml
contributions:
  capabilities:
    - point: dns-provider
      data:
        id: cloudflare
        label: Cloudflare
        acmeHook: dns_cf
        fields:
          - { name: token, label: API Token, type: password, required: true, secret: true }
        envMap: { token: CF_Token }
        ddnsProvider: cloudflare      # 可选：ddns-go 侧名称
```

- 插件为**纯声明式**（字段 schema + acme hook 名 + env 映射），无进程；
- 内核新增 `GET /api/v1/credentials/providers`，由能力注册表聚合（内置 `_core` provider 注册 `cloudflare`/`dnspod`/`aliyun`），前端凭证表单改为**按 schema 动态渲染**；
- 收敛现有 5 处硬编码为单一注册表查询；
- **dnsapi 脚本投递**：acme.sh 的 `dnsapi/*.sh` 作为 `role:assets` 制品安装到 `$DATA_DIR/tools/acme/dnsapi/`；同时修正 `source.ExtractBinary` 使其支持保留目录（当前只提取单文件）。

### 6. 卸载的运行时责任

- 卸载（`uninstall`）时：停止并移除 sidecar 进程与 pid、删除 `tools/<id>/`、注销全部贡献（能力 / 渲染器 / UI / 路由 / 菜单）、触发核心组件配方重算（ADR-038）；
- 配置与密钥保留于 BoltDB 并标记「已卸载，数据保留」；`purge` 才删除；
- 卸载后 `/api/v1/plugins/<id>/*`、`/plugins/<id>/*` 不再可达，注册表无残留。

## 本阶段实现边界

**实现**：sidecar 托管、API 反代、plugin token + scope、文件白名单强制、L0/L1 UI 宿主与 postMessage 桥、动态路由/菜单、磁盘 manifest + 在线索引 + sha256、`dns-provider` 扩展点与 providers API、dnsapi 投递与目录提取、卸载清理与配方重算。

**预留不实现**：制品签名验签、L2 远程 ESM、权限授予 UI、cgroup/namespace 隔离、sidecar 间通信、控制面管理鉴权。

## 后果

- 优点：插件逻辑与页面真正可拔插；插件与核心经统一 token/scope 边界通信；新增 DNS 供应商零内核改动；UI 强隔离，避免插件破坏核心前端。
- 代价：引入反代与 token 机制；iframe + postMessage 有宿主能力上限；sidecar 与内核同权（ADR-034 环境下的信任假设需在安装确认页显式告知）；在线索引拉取带来网络依赖与失败路径。
