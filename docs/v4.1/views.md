## 1. 参考与取舍（OxiDNS 插件中心）

### 1.1 直接照搬

| # | OxiDNS 的做法 | GateBox 对应 |
|---|---|---|
| 1 | 三视图切换（卡片 / 列表 / 拓扑） | 各页（组件 / 路由）的视图骨架 |
| 2 | 详情抽屉：配置 **表单 ↔ YAML** | 组件 / 路由的配置面 |
| 3 | **未就绪置灰**（未编译） | **未安装 + [安装]**（ADR-042 §4.1） |
| 4 | 卡片上的**运行时控件**（启停 / 重载 / 触发） | 组件的控制能力 |
| 5 | **「立即应用」** | 一键对账收敛 |
| 6 | **固定到仪表盘** | 固定到主视图 / 监控 |

### 1.2 必须改造

| OxiDNS | GateBox 改成 | 为什么 |
|---|---|---|
| 拓扑 = **静态依赖图** | **流程 / 链视图** | 静态网状图正是 V4 失败的坑；链有顺序、有实况 |
| 分类按插件角色（server/executor/matcher/provider） | 分类按 **执行者（插件 / 核心）+ 安装状态** | 我们的单位是组件，不是请求管线角色 |
| 插件 = 同质配置实例 | **插件 → 组件 → 能力** 三层 | GateBox 是异质多工具 |
| 只有"插件"一个面 | 按资源类型分页（服务 / 域名 / 部署 / 组件） | 要同时管"工具"和"声明" |

**一句话**：骨架照搬 OxiDNS，**拓扑换成链**，单一"插件"面扩成 **插件 / 组件 / 能力 / 路由** 多个面。

## 2. 视图结构（四个）

### 2.1 主视图：流量链（首页，最后做）

以**用户访问**为视角，显示每个路由的实际流程与最后状态。

```
[访问视角]  路由 aria · aria.neob.cn        最后访问 12:04:31 · 200 · 86ms   实时 ●
 ─────────────────────────────────────────────────────────────────────────────
 用户 → 入口 → WAF(Coraza) → TLS → 路由匹配 → 上游(aria2:6880) → 响应
         ✓12ms   ✓3ms        ✓8ms   ✓1ms      ✓42ms
 ─────────────────────────────────────────────────────────────────────────────
 切换：[访问视角] [事务视角]                        点任一站 → 组件详情抽屉
```

- **站** = 请求路径上的一格（组件 + 能力）。
- 每站显示**最后一次状态**（成败 / 耗时）；整条显示最近一次访问。
- **旁路**（不在 Caddy 请求路径内的）：acme（证书）、ddns（解析）以虚线挂到相关站。
- 顶部可切换 **访问视角 / 事务视角**（ADR-042 §6 的两种链）。

### 2.2 组件页（一级导航「组件」）

```
┌ 组件 ───────────────────────────────────────────────────────┐
│ [搜索]                [卡片] [列表] [流程]        [＋ 新增]   │
│ 分类: 全部 | 内置 | 插件 | 未安装                            │
├─────────────────────────────────────────────────────────────┤
│ ┌─ caddy ────────┐ ┌─ acme.sh ──────┐ ┌─ docker ───────┐   │
│ │ 入口·执行       │ │ 执行           │ │ 执行·数据源     │   │
│ │ 能力 load/serve │ │ 能力 issue     │ │ 能力 start      │   │
│ │ ✓ 运行中        │ │ ✓ 运行中        │ │ ✓ 运行中        │   │
│ └────────────────┘ └────────────────┘ └────────────────┘   │
│ ┌─ caddy-l4 ─────┐ ┌─ frankenphp ───┐                      │
│ │ 未安装 [安装]   │ │ 未安装 [安装]   │                      │
│ └────────────────┘ └────────────────┘                      │
└─────────────────────────────────────────────────────────────┘
```

- **卡片单位 = 组件**（不是插件）：插件/核心是分组与筛选维度。
- 未安装的置灰 + 一键安装（安装过程有记录）。
- 卡片上的运行时控件：启停 / 重载 / 触发。

### 2.3 组件详情抽屉

```
┌ caddy ───────────────────────────────────────── [立即应用] ┐
│ [配置] [能力] [观测] [依赖]                                  │
│ 配置：表单 ↔ YAML（form 由组件自述 schema 生成）              │
│ 能力：config.load / http.serve（可禁用 / 换实现）             │
│ 观测：状态 / 活动 / 日志 / 指标                               │
│ 依赖：需要 服务/域名/凭证 ；被 路由/链 引用                    │
└────────────────────────────────────────────────────────────┘
```

### 2.4 流程视图（替代静态拓扑）

同一批组件，两种视角并排——落地"同一组件、不同顺序、不同场景"：

```
发布任务:  caddy(主) ─分派→ docker / ddns / acme ─→ 编译 ─→ 加载 ─→ 验证
访问路由:  入口 ─→ WAF ─→ TLS ─→ 路由匹配 ─→ 上游 ─→ 响应
```

- 默认显示**最后一次状态**；历史收进**链日志**（每条链一份，可下钻 Step → 调用 → 证据）。
- 这就是"链视图 + 链日志"两种形态（ADR-042 §7）。

## 5. 名词：项目 → 服务 → 路由

```
项目 Project — 多个服务的组合（一份 compose）
 服务 Service — 编排中的一项（一个容器 / compose 的一个 service）
  路由 Route  — 一个转发，后端 = 1 个端口
```

→ 网关页列的是**路由**。

## 6. 网关页（所有已发布的路由）

### 列表列规格

| 列 | 呈现 | 悬停 |
|---|---|---|
| **路由** | 路由名 + 第二行 `[来源 icon] 服务名`（无"服务"二字） | — |
| **TLS** | 锁 icon（启用点亮 / 未启用置灰） | 到期时间 + 剩余天数 |
| **类型** | 类型 icon | 中文名 |
| **域名** | 只显 1 个；多个给 `+N` | 全部域名 |
| **入口** | 上：端口 chip（可多个）；下：协议名 | — |
| **后端** | 上：`code` 样式主内容（`ip:端口` / 文件夹 / 转发域名）；下：提示（主机名 · 服务名） | — |
| **中间件** | chip | 该中间件说明 |
| **状态** | 图标 + 状态词；下：原因 | — |
| **操作** | 统一 icon-only（**不含查看/编辑**） | 动作名 |

- **来源 icon**：docker → Docker 品牌图标（`#2496ED`）；否则 Caddy 品牌图标（`#22B638`）。图标取自 `utils/brandIcons.ts`（simple-icons）。
- **操作列**：`停止 · 重启 · 日志 · 删除`，居左对齐；**点击行即编辑**。
- **列设置**：勾选显隐 + `↑↓` 调顺序。
- **行对齐**：行高统一，单元格上下居中；有提示的显示提示行，无提示的单行居中。
- **卡片视图**：标题加大；警告/错误写在标题下方。
- **三视图**：卡片（运行情况）/ 列表（分类）/ 流程（信息流）。

### 状态列含义

| 主（状态词） | 下方提示（原因/摘要） |
|---|---|
| 已生效 | 证书有效 · 上游健康 / L4 转发（caddy-l4） |
| 证书告警 | 证书 N 天后到期 |
| 未生效 | 配置未加载 / 编译失败 |
| 已停用 | 手动暂停 |
| 错误 | 上游不可达 / 证书签发失败 |

> **状态词 = 结论，下方 = 原因**。

## 7. 新建 / 编辑界面

**抽屉**（非弹窗），基本信息固定在头部，编辑区基于模型自动生成。

```
┌ 抽屉（加宽 ~1040px）──────────────────────────────────────────────────────┐
│ ● [路由名] [类型▾] [服务]                    [表单][YAML][并排]       ×   │
├────────────────────────────────┬──────────────────────────────────────────┤
│ 表单（由模型生成）              │ YAML（等价文本，复用 CodeEditor）         │
│  域名 / 入口点 / 端口 / TLS /   │ ┌ yaml       撤销 重做 搜索 复制 ┐        │
│  中间件 / 后端                  │ │ name: aria                    │        │
│                                 │ │ ...                           │        │
├────────────────────────────────┴──────────────────────────────────────────┤
│ ✓ 校验通过                                          [取消]  [保存]        │
└──────────────────────────────────────────────────────────────────────────┘
```

- **基本信息（路由名 / 类型 / 服务）在头部，可直接编辑**（新建时也能在此填名）。
- **编辑区 = 表单 ⇄ YAML**（同一模型两种编辑面）：
  - **表单**由对象类型 + 字段 schema **自动生成**；
  - **YAML** 是同一对象的等价文本；
  - 切换时序列化 / 反序列化 + 校验（不合法标 `✗`）。
- **并排模式**（采用）：左表单 + 右 YAML，中间竖线区隔，两边即时同步；**复用 GateBox 已有的 `CodeEditor.vue`**（CodeMirror）。
- 表单区只含"可编辑字段"；名称/类型等基本信息不进表单。

## 11. 各页内容

- **域名**：根域名（+ 凭证引用）· 凭证 · 证书（到期 / 续期）
- **部署**：应用商店 · 编排（部署单元）· 容器 · 镜像 · 网络 · 存储卷
- **组件**：插件商店（未装可安装）· 已装（配置 / 能力 / 观测 / 依赖）
- **设置**：主机（`hosts` 表）· 系统（Caddy 全局 / 权限 / 版本 / 插件源）
